---
title: 'How to Prepare a Policy Release'
description: 'Configure assertions and create a release on the platform using `pcl apply`'
---

Declare your policies in `credible.toml`, then create a pending release with `pcl apply`. This guide ends with a release ready for review; signing and activation follow in [Review and Deploy Policies](./deploy-assertions-dapp#step-4-review-release-checks).

**Prerequisites**:
- Approved policies and assigned reviewers
- [pcl installed](./credible-install)
- An assertion [written](./writing-your-own-policies) and [tested](./testing-assertions)
- A [project created](./deploy-assertions-dapp#step-2-create-a-project) in the platform

## Step 1: Authenticate

Before creating the release, authenticate with the Ethereum platform:

```bash
pcl auth -u https://ethereum.phylax.systems login
```

`pcl` displays a device code and verification URL. Press Enter to open the browser. Sign in and approve the request.

<Note>
Before signing deployment, confirm that the intended Protocol Manager is authorized for the contracts in `credible.toml`. Platform login and onchain management authority are separate. See [Managing Policy Deployments](./managing-policy-deployments) for the authority boundaries and [Assign a Protocol Manager](./assign-protocol-manager) for the setup task.
</Note>

Check your status anytime:

```bash
pcl auth status
```

For Ethereum production, complete [guard coverage, routing, and recovery planning](./dapp-integration) separately. Creating or activating a release does not configure those controls.

## Step 2: Configure `credible.toml`

Create `assertions/credible.toml` to declare the protected contracts and their assertions. These examples prepare an **Alerting** release so you can observe policy behavior. For an approved production rollout, set `environment = "production"` after completing the [integration test plan](./testing-strategy). Replace the address and file placeholders with your reviewed targets:

```toml
environment = "alerting"

[contracts.my_contract]
address = "0xYOUR_CONTRACT_ADDRESS"
name = "MyContract"

[[contracts.my_contract.assertions]]
file = "assertions/src/MyAssertion.a.sol"
```

To protect multiple contracts, add more entries:

```toml
environment = "alerting"

[contracts.vault]
address = "0xVAULT_ADDRESS"
name = "Vault"

[[contracts.vault.assertions]]
file = "assertions/src/VaultAssertion.a.sol"

[contracts.token]
address = "0xTOKEN_ADDRESS"
name = "Token"

[[contracts.token.assertions]]
file = "assertions/src/TokenDrainAssertion.a.sol"
```

<Note>
Each contract address must be unique within the configuration. See the [pcl Reference](./cli-reference#credible-toml-configuration) for all available fields.
</Note>

<Tip>
Set `project_id` to skip interactive project selection, including in CI. This is also required for local-only `pcl apply --dry-run` validation. Without it, dry-run authenticates and queries the platform to select a project; it still does not create a release.
</Tip>

<Note>
Declare the complete policy set for the replacement release, including policies you want to retain. Omitting a contract or assertion proposes its removal as part of that release; it does not remove an assertion individually from the active release. Review the full diff before signing. Changes take effect after deployment approval and the State Oracle delay.
</Note>

## Step 3: Apply Your Assertions

Create a release on the platform:

```bash
pcl apply
```

The command builds the configured assertions and previews changes against the project state. Confirm to create a pending release.

You'll be prompted to confirm before applying. Use `--yes` to skip the confirmation prompt:

```bash
pcl apply --yes
```

<Note>
`pcl apply` automatically builds your project. You can also run `pcl build` separately to check for compilation errors before applying.
</Note>

## Step 4: Verify the Prepared Release

Open the new release under **Releases** in the selected project. Confirm its environment, target contracts, and complete assertion additions and removals against the preview you approved.

The result is a pending release, not active protection. Continue directly to [Step 4: Review Release Checks](./deploy-assertions-dapp#step-4-review-release-checks); do not repeat authentication, project creation, or `pcl apply`. An authorized manager must then sign deployment, and activation follows the configured delay.

## Troubleshooting

### Authentication Issues

| Error | Solution |
|-------|----------|
| "Not authenticated" | Run `pcl auth -u https://ethereum.phylax.systems login` |
| "Authentication expired" | Run `pcl auth -u https://ethereum.phylax.systems login` to refresh |
| Browser doesn't open | Manually visit the URL shown in terminal |

### Apply Issues

| Error | Solution |
|-------|----------|
| "credible.toml not found" | Check that the file exists at `assertions/credible.toml` or specify the path with `-c` |
| "duplicate contract address" | Each contract address must be unique in `credible.toml` |
| "Project not found" | Create the project in the platform first, or set `project_id` in `credible.toml` |
| Build failures | Run `pcl build` separately to diagnose compilation errors |
