title: 'Apply Assertions'

---

Declare your policies in `credible.toml`, then create a release with `pcl apply`.

**Prerequisites**:
- Approved policies and assigned reviewers
- [pcl installed](/credible/credible-install)
- An assertion [written](./writing-your-own-policies) and [tested](/credible/testing-assertions)
- A [project created](/credible/deploy-assertions-dapp#step-2-create-a-project) in the platform

## Step 1: Authenticate

Before deploying, authenticate with the Credible Layer:

```bash
pcl auth -u https://ethereum.phylax.systems login
```

`pcl` displays a device code and verification URL. Press Enter to open the browser. Sign in and approve the request.

<Note>
Confirm that the intended Protocol Manager is authorized for the contracts in `credible.toml`. Platform login and on-chain management authority are separate. See [Managing Policy Deployments](./managing-policy-deployments) for the supported authorization path.
</Note>

Check your status anytime:

```bash
pcl auth status
```

For Ethereum production, complete [guard coverage, routing, and recovery planning](./dapp-integration) separately. Creating or activating a release does not configure those controls.

## Step 2: Configure `credible.toml`

Create `assertions/credible.toml` to declare the protected contracts and their assertions:

```toml
environment = "production"

[contracts.my_contract]
address = "0xYOUR_CONTRACT_ADDRESS"
name = "MyContract"

[[contracts.my_contract.assertions]]
file = "assertions/src/MyAssertion.a.sol"
```

To protect multiple contracts, add more entries:

```toml
environment = "production"

[contracts.vault]
address = "0xVAULT_ADDRESS"
name = "Vault"

[[contracts.vault.assertions]]
file = "assertions/src/VaultAssertion.a.sol"

[contracts.token]
address = "0xTOKEN_ADDRESS"
name = "Token"

[[contracts.token.assertions]]
file = "assertions/src/TokenDrainAssertion.a.sol"
```

<Note>
Each contract address must be unique within the configuration. See the [pcl Reference](/credible/cli-reference#credibletoml-configuration) for all available fields.
</Note>

<Tip>
Set `project_id` to skip interactive project selection, including in CI.
</Tip>

<Note>
Omitting a contract or assertion requests its removal. The removal takes effect after deployment approval and the State Oracle delay.
</Note>

## Step 3: Apply Your Assertions

Create a release on the platform:

```bash
pcl apply
```

The command builds the configured assertions and previews changes against the project state. Confirm to create a pending release.

You'll be prompted to confirm before applying. Use `--yes` to skip the confirmation prompt:

```bash
pcl apply --yes
```

<Note>
`pcl apply` automatically builds your project. You can also run `pcl build` separately to check for compilation errors before applying.
</Note>

## Step 4: Review and Deploy in the Platform

Open the release under **Releases** in your project. Review the diff and [release checks](./release-review-checks), then follow [Deploy Assertions](./deploy-assertions-dapp#step-4-deploy-the-assertion).

The release becomes active after an authorized manager signs the deployment and the State Oracle delay expires.

## Troubleshooting

### Authentication Issues

| Error | Solution |
|-------|----------|
| "Not authenticated" | Run `pcl auth -u https://ethereum.phylax.systems login` |
| "Authentication expired" | Run `pcl auth -u https://ethereum.phylax.systems login` to refresh |
| Browser doesn't open | Manually visit the URL shown in terminal |

### Apply Issues

| Error | Solution |
|-------|----------|
| "credible.toml not found" | Check that the file exists at `assertions/credible.toml` or specify the path with `-c` |
| "duplicate contract address" | Each contract address must be unique in `credible.toml` |
| "Project not found" | Create the project in the platform first, or set `project_id` in `credible.toml` |
| Build failures | Run `pcl build` separately to diagnose compilation errors |
