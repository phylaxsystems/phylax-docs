---
title: 'How to Request Manual Verification'
description: 'Prepare an assertion-manager authorization request for contracts without a supported automatic verifier.'
---

Use this guide when your contracts do not fit the target deployment's automatic verification path. Confirm that manual registration is supported before preparing the request.

## Prerequisites

- Identify the network and contracts requiring assertion-management authorization.
- Identify the intended Protocol Manager address and its signing policy.
- Be able to demonstrate that the protocol authorizes that manager for those contracts.

## 1. Confirm the Verification Path

Check the supported verifier with Phylax. An ownership interface such as `owner()` or an explicit initial Protocol Manager interface may provide an automatic path. Existing contracts without a suitable interface may require manual review.

Do not change contract ownership or add an interface solely to satisfy an assumed requirement. See [Ownership Verification](./ownership-verification).

## 2. Prepare the Request

Provide the target network, contract addresses, intended manager, and an explanation of the protocol's ownership and governance structure. Include evidence demonstrating control and consent, such as an authorization from the existing admin multisig or governance process and control of the official codebase.

Confirm the required evidence with Phylax. Public codebase access alone should not be treated as authority to change a protocol's security policy.

## 3. Review Registration and Recovery

Agree on the contract set, authorization path, applicable delays, and how manager changes or key loss will be handled. Review any separate protocol, guard, and Registry powers. Manual approval is not a substitute for this authority review.

## 4. Verify the On-Chain Result

After an approved registration is executed, verify that the State Oracle associates the intended manager with the agreed contracts. Check any pending activation time and confirm the manager can perform the expected lifecycle actions.

Then follow [Integration Planning](./dapp-integration) and [Deploy Assertions](./deploy-assertions-dapp). Registration alone does not establish guard coverage or transaction routing.
