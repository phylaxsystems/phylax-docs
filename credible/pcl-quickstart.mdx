title: 'Run an Example Policy Locally'

---

Run an example policy that rejects ownership changes. Inspect its passing and failing cases in local tests.

## Prerequisites

- [pcl installed](./credible-install)
- Git and Foundry available locally

No wallet or live transaction is required.

## 1. Clone the Starter

Clone the example project with its dependencies:

```bash
git clone --recurse-submodules https://github.com/phylaxsystems/credible-layer-starter.git
cd credible-layer-starter
```

The project contains example protocol contracts in `src`, assertions in `assertions/src`, and tests in `assertions/test`.

## 2. Run the Tests

From the repository root, run:

```bash
pcl test
```

The command compiles the project and runs the assertion tests. The output includes these two Ownable cases; gas values and timing vary:

```text
[PASS] test_assertionOwnershipChanged()
[PASS] test_assertionOwnershipNotChanged()
```

A passing ownership-change test means the test correctly observed the expected assertion rejection. It does not mean the rule permits ownership changes.

## 3. Inspect the Rule and Its Tests

Open `assertions/src/OwnableAssertion.a.sol` and `assertions/test/OwnableAssertion.t.sol`.

The rule compares the owner before and after the candidate operation. In the test, `cl.assertion()` registers the assertion for the next external call. One case attempts a change and expects the assertion to revert; the other leaves the owner unchanged and passes.

This rule rejects legitimate ownership transfers too. For a real protocol, define which changes should be allowed before adapting the example.

## 4. Understand What You Have Verified

The tests check ownership changes in the local harness. The starter contract has no Ethereum guard, so these tests do not establish production protection.

Use the current [Ethereum integration guide](./dapp-integration) instead of the starter's earlier deployment instructions.
