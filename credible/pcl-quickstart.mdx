In this tutorial, you will run a working assertion project and inspect a rule that rejects ownership changes. You will finish with a locally tested assertion and know which integration steps are needed before it can protect Ethereum operations.

## Prerequisites

- [pcl installed](./credible-install)
- Git and Foundry available locally

This tutorial runs local tests. It does not require a wallet, a funded account, or a live transaction.

## 1. Clone the Starter

Clone the example project with its dependencies:

```bash
git clone --recurse-submodules https://github.com/phylaxsystems/credible-layer-starter.git
cd credible-layer-starter
```

The project contains example protocol contracts in `src`, assertions in `assertions/src`, and tests in `assertions/test`.

## 2. Run the Tests

From the repository root, run:

```bash
pcl test
```

The command compiles the project and runs the assertion tests. The output includes these two Ownable cases; gas values and timing vary:

```text
[PASS] test_assertionOwnershipChanged()
[PASS] test_assertionOwnershipNotChanged()
```

A passing ownership-change test means the test correctly observed the expected assertion rejection. It does not mean the rule permits ownership changes.

## 3. Inspect the Rule and Its Tests

Open `assertions/src/OwnableAssertion.a.sol` and `assertions/test/OwnableAssertion.t.sol`.

The rule compares the owner before and after the candidate operation. In the test, `cl.assertion()` registers the assertion for the next external call. One case attempts a change and expects the assertion to revert; the other leaves the owner unchanged and passes.

This rule rejects legitimate ownership transfers too. For a real protocol, define which changes should be allowed before adapting the example.

## 4. Understand What You Have Verified

The tests establish that the example detects an ownership change under its local test conditions. They do not install a guard, activate an assertion, or exercise the Ethereum builder path.

Ethereum builders that do not participate can include transactions without running assertions. The starter's unguarded Ownable contract is therefore not a production Ethereum protection setup. A timeout after submitting a transaction would not prove assertion enforcement either.

The starter also contains earlier live-deployment instructions. Use the Ethereum guides below for platform selection and enforcement requirements.

## Continue to Ethereum Integration

You now have a local example you can inspect and modify. To use an assertion on Ethereum:

1. [Plan the integration](./dapp-integration): identify protected operations, required guards, transaction submitters, authority, and recovery.
2. [Apply assertions](./apply-assertions): authenticate explicitly with the Ethereum platform and prepare a release for reviewed target contracts.
3. [Deploy through the platform](./deploy-assertions-dapp): review staging evidence and schedule activation through the authorized manager.
4. [Test the full integration](./testing-strategy): verify guarded execution, routing, assertion rejection, and recovery before production.
