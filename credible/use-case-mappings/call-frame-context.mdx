Call context identifies the function call that dispatched an assertion. Use its start and end snapshots to evaluate that operation, rather than only the whole transaction's endpoints.

## Status

**Spec:** Reshiram. **Evidence:** API reference, with a [tested local oracle fixture](../../assertions-book/assertions/ass28-intra-tx-oracle-deviation) illustrating a post-call check. That fixture does not establish coverage for every batching or proxy design.

## API and Behavior

| Interface | Purpose |
| --- | --- |
| `registerFnCallTrigger` | Select the function calls that dispatch the assertion |
| [`context()`](../cheatcodes-reference#trigger-context) | Read the matched call's `callStart` and `callEnd` identifiers |
| [`getCallInputs(target, selector)`](../cheatcodes-reference#getcallinputs) | Inspect recorded arguments and call IDs; use the entry matching the trigger context |
| [`loadStateAt(target, slot, fork)`](../cheatcodes-reference#loadstateat) | Read a slot at the explicitly selected snapshot |

## Snapshot Selection

| Boundary | `forkType` | `callIndex` |
| --- | --- | --- |
| Before the matched call | `2` | `context().callStart` |
| After the matched call | `3` | `context().callEnd` |

Use the same matched context for both reads. When inspecting arguments, require a matching call record before decoding it; a default or unrelated record is not a substitute.

<span id="example-use-cases" />

## Choosing the Observation Boundary

A transaction can update an oracle twice, first outside the policy's bounds and then back inside them. An endpoint-only check can miss that excursion. The [oracle fixture](../../assertions-book/assertions/ass28-intra-tx-oracle-deviation) checks covered updates separately and tests this change-and-restore case.

For a transfer policy, compare balances across the covered external call and define the expected result for self-transfers, fees, and nested operations. An internal Solidity function invocation does not necessarily create a separate EVM call frame; a batch function therefore needs its own coverage analysis.

<span id="implementation-considerations" />

## Coverage Limits

A call's end snapshot includes changes made by its nested execution. Recursive calls, alternate selectors, delegatecalls, and proxy storage require explicit tests. Checking one selected frame does not establish that all state-changing paths dispatch the assertion.
