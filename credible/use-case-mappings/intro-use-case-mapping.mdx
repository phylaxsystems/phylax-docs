title: Use Case Mappings
description: Reference for choosing assertion inspection capabilities and understanding their constraints.
---

Choose the data your assertion needs to inspect. Each reference describes the interface, snapshot scope, and implementation constraints; a supported API does not make every illustrative fragment a tested fixture.

<span id="what-youll-find-here" />

| Need | Reference | Main constraint |
| --- | --- | --- |
| Inspect arguments of matching calls | [Function Call Inputs](./function-call-inputs) | Account for every relevant state-changing entry point |
| Reconcile emitted events with state | [Read Logs](./read-logs) | Filter emitter/signature; events can omit changes |
| Read a known storage slot | [Storage Lookup](./storage-lookups) | Know the layout and select the intended snapshot |
| Inspect writes during a transaction | [State Change Tracking](./state-changes) | Distinguish intermediate writes from endpoint values |
| Check one matched call | [Call Frame Context](./call-frame-context) | Use the matching call's start/end snapshots |
| Discover written mapping keys | [Modified Key Discovery](./modified-keys) | Best-effort Reshiram discovery; no full mapping enumeration |

Confirm the target runtime supports the required [assertion specification](../assertions-overview#assertion-specifications). For a guided exercise with expected results, use [Run an Example Policy Locally](../pcl-quickstart).
