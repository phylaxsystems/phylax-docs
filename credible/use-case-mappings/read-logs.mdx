---
title: Read Logs
description: Filter recorded events and compare their claims with actual state changes.
---

Logs describe what a contract emitted. An assertion can compare those claims with storage snapshots; an event alone is not proof that the corresponding state change occurred.

## Status

**Spec:** Reshiram. **Evidence:** locally tested fixture. **Scope:** non-indexed `Added(uint256)` events from a counter with a `uint256` in slot zero.

## API and behavior

Use `getLogsQuery(query, fork)` for snapshot-aware log inspection and `getLogsForCall(query, callId)` for a call scope. The older `getLogs()` selector is rejected under Reshiram in the tested PCL 1.9.0 runtime.

`LogsAssertion` below reads transaction logs at `_postTx()`. It checks the emitter, topic count, and event signature before decoding the non-indexed amount. It compares the summed amounts with the actual slot-zero change. Indexed parameters belong in topics and require a different decoder.

The complete fixture and tests are in `examples/docs` in the documentation repository. The three assertions were exercised with PCL 1.9.0, Solidity 0.8.29, and credible-std `fe49de6dcddb8ea1f77ea2828a0c9d7d5f923db0` on Linux ARM64 (November 17, 2026): 14 tests pass, including four fuzz tests with 256 runs each. This establishes local behavior, not production dispatch or historical exploit prevention.

## Coverage limits

The tests cover two additions, incorrect event amounts, a silent state write, unrelated signatures, and another emitter. A silent write is caught because the slot comparison is independent of the events. If events are also the only way to discover affected accounts, a silent write to an undiscovered account can still escape the check.

The example does not cover reverted child calls, proxy emission addresses, rebasing tokens, or ERC-20 transfer accounting. Use [Call Frame Context](./call-frame-context) when intermediate state matters and [Modified Key Discovery](./modified-keys) for its supported mapping-key discovery cases.
