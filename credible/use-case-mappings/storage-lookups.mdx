Storage lookup reads a raw slot without requiring a public getter. The caller must supply the correct contract address, storage layout, and snapshot.

## Status

**Spec:** Reshiram for explicit snapshots. **Evidence:** API reference; this page does not provide a standalone tested policy. The [ownership tutorial](../../assertions-book/assertions/run-an-example) exercises endpoint reads in a local fixture.

## API and Behavior

[`loadStateAt(target, slot, fork)`](../cheatcodes-reference#loadstateat) returns the slot's `bytes32` value at the supplied `ForkId`.

| Snapshot | Question it answers |
| --- | --- |
| `_preTx()` | What was the value before the transaction? |
| `_postTx()` | What was the value after the transaction? |
| Matched call start/end | What changed across this particular call? See [Call Frame Context](./call-frame-context). |

## Interpreting a Slot

For an unpacked owner address in slot zero, decode the low 160 bits as an address. This layout is a property of that contract, not a general ownership convention. A proxy implementation slot, packed variable, or mapping entry requires its own layout and decoding.

Two possible owner policies answer different questions:

- **Endpoint lock:** compare pre- and post-transaction values to reject a permanent change.
- **Allowlist:** compare the selected snapshot's owner with an approved set to restrict who may own the contract.

Neither comparison establishes that every intermediate owner was allowed. Use [State Change Tracking](./state-changes) when that is the requirement.

## Coverage Limits

- Read from the address that holds the storage. In a delegatecall-based proxy, this can differ from the implementation code's address.
- Calculate mapping slots and apply the correct offsets and masks for packed fields. See [Modified Key Discovery](./modified-keys) for its separate discovery constraints.
- Confirm the deployed runtime supports the requested specification. A local endpoint test does not establish production coverage.
