State-change tracking returns the recorded values written to a known storage slot during a transaction. It can reveal a temporary change even when the final value equals the initial value.

## Status

**Evidence:** API reference and worked reasoning examples below, not an executable policy fixture. Confirm the target runtime's [assertion specification](../cheatcodes-reference#assertion-specs) before combining write observations with snapshot reads.

## API and Behavior

[`getStateChanges(target, slot)`](../cheatcodes-reference#getstatechanges) returns the recorded writes for that slot in order. The pre-transaction value is not included. The [typed helpers](../credible-std-overview#state-change-helpers) decode those values; they do not infer the contract's storage layout.

## Comparing Writes with a Policy

For a nondecreasing-value policy, read the pre-transaction value as the baseline. Compare each recorded value with the previous value, then advance the baseline. An empty write list has no transition to reject. For a strictly increasing policy, equal consecutive values must also fail.

| Initial value | Recorded writes | Nondecreasing result | Reason |
| --- | --- | --- | --- |
| 10 | None | Accept | No observed change |
| 10 | 11 | Accept | The first write meets the baseline |
| 10 | 9 | Reject | The first write violates the baseline |
| 10 | 11, 10 | Reject | A later decrease is visible despite equal transaction endpoints |
| 10 | 10 | Accept | Equality is permitted by this policy |

For an authority lock, compare every recorded authority value with the permitted value or allowlist instead. The [ownership tutorial](../../assertions-book/assertions/run-an-example) demonstrates why endpoint equality alone cannot rule out a temporary authority change; it does not test a write-tracking replacement.

## Coverage Limits

- Observations are slot-level. Decode packed fields with the contract's offsets and masks before comparing values.
- Derive mapping slots from the layout, or use [Modified Key Discovery](./modified-keys) within its discovery limits.
- Separate slots have separate write lists. Matching array indices does not establish that two values existed at the same moment. Use [call snapshots](./call-frame-context) when a policy needs a defined boundary across multiple slots.
- Validate reverted calls, nested execution, and trigger coverage in the target runtime before treating an observed write sequence as proof of protection.
