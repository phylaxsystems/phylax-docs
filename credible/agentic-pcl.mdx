Use an AI coding agent to implement, test, and prepare policy releases with `pcl`. Review its output against the agreed requirements.

Phylax provides reusable workflows in the [agent-skills repository](https://github.com/phylaxsystems/agent-skills).

## Prerequisites

- [`pcl` installed](./credible-install)
- An agent that supports the [Agent Skills format](https://agentskills.io), such as Codex or Claude Code
- A local protocol repository the agent can inspect and edit
- For custom integration work, defined policy requirements and assigned review responsibilities

For deployment, you also need a target chain, an RPC endpoint, and access to the protocol manager wallet.

Authenticate with the platform for your target network before starting the agent. See [Deploy Policies with an AI Agent](./agentic-pcl-deploy#1-authenticate-manually) for explicit Ethereum platform selection. The earlier L2 workflow is in [L2 Platform Notes](./l2-integrations/platform-and-compatibility).

<Warning>
An agent can edit code, create platform resources, and broadcast on-chain transactions. Review its plan and local changes before authorizing remote mutations. Require a successful dry run and explicit approval before any production deployment.
</Warning>

## Choose the workflow

| Goal | Skill | What the agent should do |
| --- | --- | --- |
| Create an assertion project | `pcl-assertion-workflow` | Inspect the protocol, create the assertion project structure, configure dependencies, and run local tests |
| Deploy through the platform | `deploy-credible-assertions` | Use the existing authentication, check RPC configuration, create or resolve the platform project, create a release, and activate it on-chain |

Use the skill name in your request so the intended workflow is unambiguous.

## Start with a high-level prompt

Give the agent the approved policies, target contracts, and test requirements. Require review of unresolved requirements and proposed policy changes.

For example:

```text
Use the Phylax agent skills to implement and test the agreed custom policies.

Policy specification approved by our team: <path>
Protocol contracts and deployment records: <paths>
Required allowed, rejected, and exception cases: <path>

Explain how the implementation maps to the specification. Surface any missing
requirements, uncovered paths, or proposed behavior changes for review.
Run the relevant pcl tests and report their results and limitations.

Do not change the policy requirements, create platform resources, access
signing credentials, or deploy anything as part of this task.
```

## Orient the agent with the installed CLI

Current versions of `pcl` expose machine-readable guidance for agents. Include this instruction in your prompt:

```text
Before acting, inspect the installed pcl version, its machine-readable agent
guide, and the help for the relevant workflow command. Treat the installed CLI
as the source of truth. Prefer top-level workflow commands, structured JSON
output, and the next actions returned by pcl.
```

This gives the agent guidance for the installed CLI version.

## Keep a human in the approval loop

Authenticate before starting the deployment agent. Allow local inspection, edits, builds, and tests. Approve the environment, platform changes, and signer use before deployment.

Do not paste a private key into the conversation or commit it to the repository. Prefer a Foundry keystore and provide its password through a file outside the project.
