Add `pcl test` to your CI workflow to check assertions before merging.

This workflow validates assertion logic. Add separate checks for your Ethereum guard wiring, upgrade compatibility, and recovery behavior; passing `pcl test` does not prove the live submission route. See [Testing Strategy](./testing-strategy).

## GitHub Actions Example

```yaml
name: Phylax Assertion Tests

on:
  pull_request:
    branches: [main, develop]
    paths:
      - "assertions/**"
      - "src/**"
  workflow_dispatch:

env:
  FOUNDRY_PROFILE: assertions

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4
        with:
          submodules: recursive

      - name: Setup Foundry
        uses: foundry-rs/foundry-toolchain@v1
        with:
          version: nightly

      - name: Install pcl
        run: |
          LATEST_VERSION=$(curl -fsSL https://api.github.com/repos/phylaxsystems/pcl/releases/latest | jq -r '.tag_name')
          curl -fsSL "https://github.com/phylaxsystems/pcl/releases/download/${LATEST_VERSION}/pcl-${LATEST_VERSION}-linux-x86_64.tar.gz" | tar -xz
          sudo install -m 0755 pcl/pcl /usr/local/bin/pcl

      - name: Run tests
        run: |
          pcl test
```

The workflow runs `pcl test` with the `assertions` profile on matching pull requests or manual dispatch. It installs the latest `pcl`. Pin a version for reproducible runs.

## Foundry Profile Configuration

Use profiles in `foundry.toml` to separate unit and fuzz tests.

### Recommended Profile Structure

Organize your tests into separate folders and create profiles for each test type:

```
assertions/
├── src/           # Assertion source code
└── test/
    ├── unit/      # Fast unit tests
    └── fuzz/      # Fuzz tests (slower)
```

### Example foundry.toml

```toml
[profile.default]
src = "src"
out = "out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 200

# General assertions profile (runs all tests)
[profile.assertions]
src = "assertions/src"
test = "assertions/test"
out = "assertions/out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 200

# Unit tests only (fast, for local development)
[profile.unit-assertions]
src = "assertions/src"
test = "assertions/test/unit"
out = "assertions/out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 200

# Fuzz testing profile
[profile.fuzz-assertions]
src = "assertions/src"
test = "assertions/test/fuzz"
out = "assertions/out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 10000

# Fuzz configuration (applies to all profiles)
[fuzz]
runs = 256
max_test_rejects = 65536
```

### Profile Benefits

Use `unit-assertions` for unit tests, `fuzz-assertions` for fuzz tests, and `assertions` for the full suite.

## Running Tests Locally with Profiles

You can set the `FOUNDRY_PROFILE` environment variable to use specific profiles:

```bash
# Run only fast unit tests (recommended for local development)
FOUNDRY_PROFILE=unit-assertions pcl test

# Run fuzz tests
FOUNDRY_PROFILE=fuzz-assertions pcl test

# Run all assertion tests
FOUNDRY_PROFILE=assertions pcl test
```

If nothing is specified, the default profile is used.

## Best Practices

1. **Run tests on PR** - Catch issues before merging
2. **Use path filters** - Only run tests when relevant files change
3. **Cache dependencies** - Speed up CI runs (Foundry toolchain action handles this)
4. **Separate profiles** - Keep assertion compilation separate from main project
5. **Pin versions** - Consider pinning the `pcl` version for reproducibility
