Add `pcl test` to your CI workflow to check assertions before merging.

This workflow validates assertion logic. Add separate checks for your Ethereum guard wiring, upgrade compatibility, and recovery behavior; passing `pcl test` does not prove the live submission route. See [Testing Strategy](./testing-strategy).

## GitHub Actions Example

```yaml
name: Phylax Assertion Tests

on:
  pull_request:
  workflow_dispatch:

permissions:
  contents: read

env:
  FOUNDRY_PROFILE: assertions
  PCL_VERSION: "1.9.0"

jobs:
  test:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
        with:
          submodules: recursive
      - name: Install pinned pcl
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh release download "$PCL_VERSION" --repo phylaxsystems/pcl \
            --pattern "pcl-${PCL_VERSION}-linux-x86_64.tar.gz"
          tar -xzf "pcl-${PCL_VERSION}-linux-x86_64.tar.gz"
          sudo install -m 0755 pcl/pcl /usr/local/bin/pcl
          pcl --version
      - name: Run assertion tests
        run: pcl test
```

Run this workflow on every pull request so changes to dependency pins, submodules, compiler settings, remappings, fixtures, and the workflow itself cannot bypass it. Commit dependency revisions and use the profile below. `pcl` supplies its test runner and obtains the configured Solidity compiler; this recipe does not require a moving Foundry nightly.

The CLI was exercised locally on Linux ARM64. The documentation repository also ran its observation fixtures successfully on GitHub-hosted Ubuntu x86-64 with this release asset and compiler pin. Your workflow still needs to validate its own dependencies, profiles, and tests.

## Foundry Profile Configuration

Use profiles in `foundry.toml` to separate unit and fuzz tests.

### Recommended Profile Structure

Organize your tests into separate folders and create profiles for each test type:

```text
assertions/
├── src/           # Assertion source code
└── test/
    ├── unit/      # Fast unit tests
    └── fuzz/      # Fuzz tests (slower)
```

### Example foundry.toml

```toml
[profile.default]
src = "src"
out = "out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 200

# General assertions profile (runs all tests)
[profile.assertions]
src = "assertions/src"
test = "assertions/test"
out = "assertions/out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 200

# Unit tests only (fast, for local development)
[profile.unit-assertions]
src = "assertions/src"
test = "assertions/test/unit"
out = "assertions/out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 200

# Fuzz testing profile
[profile.fuzz-assertions]
src = "assertions/src"
test = "assertions/test/fuzz"
out = "assertions/out"
libs = ["lib"]
solc = "0.8.29"
optimizer = true
optimizer_runs = 10000

# Fuzz configuration inherited from the default profile
[profile.default.fuzz]
runs = 256
max_test_rejects = 65536
```

### Profile Benefits

Use `unit-assertions` for unit tests, `fuzz-assertions` for fuzz tests, and `assertions` for the full suite.

## Running Tests Locally with Profiles

You can set the `FOUNDRY_PROFILE` environment variable to use specific profiles:

```bash
# Run only fast unit tests (recommended for local development)
FOUNDRY_PROFILE=unit-assertions pcl test

# Run fuzz tests
FOUNDRY_PROFILE=fuzz-assertions pcl test

# Run all assertion tests
FOUNDRY_PROFILE=assertions pcl test
```

If nothing is specified, the default profile is used.

The TOML above was exercised with the [local observation fixtures](https://github.com/phylaxsystems/phylax-docs/tree/main/examples/docs) on November 17, 2026: `assertions` ran 14 tests, `unit-assertions` ran 10, and `fuzz-assertions` ran four with 256 runs each. All passed using PCL 1.9.0 and Solidity 0.8.29.

## Best Practices

1. **Run tests on PR** - Catch issues before merging
2. **Cover configuration changes** - Run on every PR unless an exhaustive path filter is maintained
3. **Commit dependency pins** - Reproduce the same library and submodule revisions
4. **Separate profiles** - Keep assertion compilation separate from main project
5. **Pin versions** - Update PCL and compiler pins together with test evidence
