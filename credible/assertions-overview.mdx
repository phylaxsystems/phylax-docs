An assertion is a Solidity function that rejects transaction effects that violate a policy. A policy defines the intended behavior and exceptions. Assertions implement its checks.

Assertions describe invalid outcomes without predicting every exploit path. Participating builders enforce them before inclusion. See [Ethereum Architecture](./architecture-overview) for guards and routing.

## Assertion Specifications

- **Legacy (V1)** exposes the original PhEVM precompiles, including mutable fork switching with `forkPreTx`, `forkPostTx`, and `forkPostCall`.
- **Reshiram (V2)** replaces mutable fork switching with immutable `ForkId` snapshot reads and adds newer transaction and call inspection precompiles.

<Warning>
Confirm which specification your target Ethereum deployment accepts before activation. Library availability and local tests do not establish enforcer compatibility. Earlier Linea-specific restrictions are in [L2 Platform Notes](./l2-integrations/platform-and-compatibility#assertion-specifications).
</Warning>

## How Assertions Work

[Triggers](./triggers) select assertion functions for relevant transaction activity. [PhEVM](./phevm) executes them against state snapshots. A participating builder excludes a candidate if an active production assertion fails.

## Example: Prevent Unauthorized Ownership Changes

```solidity
function checkOwnershipChange() external view {
    PhEvm.ForkId memory preTx = _preTx();
    PhEvm.ForkId memory postTx = _postTx();

    address ownerBefore = address(uint160(uint256(ph.loadStateAt(address(protocol), bytes32(uint256(0)), preTx))));
    address ownerAfter = address(uint160(uint256(ph.loadStateAt(address(protocol), bytes32(uint256(0)), postTx))));

    require(ownerBefore == ownerAfter, "Owner cannot change");
}
```

With an appropriate trigger, this rule rejects ownership changes, including legitimate transfers. Add explicit exceptions if the policy permits transfers.

## What They Can Do That Regular Solidity Can't

Assertions can read state before and after a transaction or matched call. They can inspect interactions across contracts and check their combined effects.

Rules execute offchain with separate gas limits. Teams can update policy without changing protocol logic, once the required Ethereum guard is installed. See [Cheatcodes](./cheatcodes-overview) for state access.

## Common Use Cases

Policies can restrict administrative changes, token outflows, price deviations, and accounting violations. See the [Assertion Pattern Catalog](../assertions-book/assertions/use-cases-index).

## Constraints

The default assertion gas limit is 3,000,000. Operators can configure it. Exceeding the limit invalidates the candidate.

Use scoped triggers and test the maximum expected workload. See [Gas Limits in Testing](./testing-assertions#gas-limits).
