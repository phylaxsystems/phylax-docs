Choose a pattern by the transaction you need to constrain. Each reference describes the measured quantity, configuration, expected outcomes, and coverage limits.

This edition is reviewed against [credible-std at `fe49de6`](https://github.com/phylaxsystems/credible-std/tree/fe49de6dcddb8ea1f77ea2828a0c9d7d5f923db0), source dated October 28, 2026; documentation reviewed November 17, 2026. Examples are starting points for a policy tied to your deployed contracts. **A contract with no registered triggers enforces nothing.**

## Choose a starting point

- [Test the limits of an ownership policy](./run-an-example): execute a permitted operation, reject an ownership change, and verify rollback.
- [Compose an ERC-4626 policy](./vault-policies): combine call-level share-price checks with a rolling outflow cap.
- [Configure a Balancer Vault breaker](./balancer-outflow): select the custody address, token, threshold, and window.
- [Reusable patterns](./reusable-patterns): accounting, call results, account health, oracle gates, configuration, and tiered limits.

| [Borrowed supply bound](./ass19-tokens-borrowed-invariant) | Recorded borrowing does not exceed recorded supply |

## Legacy examples requiring adaptation

These legacy pages retain their source for comparison and explain the replacement approach. They are not deployment-ready policies.

| Example | Required correction |
| --- | --- |
| [Oracle freshness](./ass10-oracle-validation) | Bind the oracle and timestamp read to the operation's snapshot |
| [TWAP deviation](./ass11-twap-deviation) | Use snapshot reads and an exact scaled comparison |
| [Tick bounds and spacing](./ass15-price-within-ticks) | Apply spacing to initialized ticks, not the current pool tick |
| [Liquidation health improvement](./ass16-liquidation-health-factor) | Read distinct pre- and post-call states and match liquidation semantics |

For production preparation, follow [Ethereum assertion testing](../../credible/testing-strategy). The [hack case studies](../previous-hacks/prev-hacks-index) provide historical context rather than proof that an example covers every attack path.

## Read the catalog facets

| Facet | Meaning | Where to look |
| --- | --- | --- |
| Risk domain | Flow, authority/configuration, accounting, solvency, or valuation | Pattern groups above and [case studies](../previous-hacks/prev-hacks-index) |
| Protocol family | The storage and economic model being adapted | [Aave](./aave-v3-suite), [ERC-4626](./vault-policies), [Balancer custody](./balancer-outflow), and historical [Optimism FMA](./optimism-fma-suite) |
| Dispatch mechanism | When the runtime invokes the assertion | [Triggers](../../credible/triggers); [anomaly gating](./anomaly-gated-policies) is a dispatch choice, not a separate risk domain |
| Specification | APIs the assertion requests | [Legacy, Reshiram, and Experimental](../../credible/cheatcodes-reference#assertion-specs) |
| Lifecycle | Current example, legacy adaptation, or historical design | The entry's status and limitations |
| Evidence | Source review, compilation, local behavior tests, exploit replay, or live enforcement | The entry's stated validation; one level does not imply another |

Imported Book sources compile at the pinned revision, but most are not individually behavior-tested by this documentation review. The ownership tutorial and local observation fixtures identify their executed tests. Read warnings before copying an example.
