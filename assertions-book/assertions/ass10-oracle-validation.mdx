A swap depends on a price that may not have been updated recently. `OracleLivenessAssertion` registers `swap(address,address,uint256)` and requires the oracle's reported update time to be no more than 600 seconds old.

<Warning>
The reviewed upstream example needs correction before production use. The limitation below is present in the linked source; the imported code is preserved for comparison.
</Warning>

## Source limitation

The example creates a post-transaction fork identifier but does not use it for its oracle reads. It calls `oracle()` and `lastUpdated()` directly. Creating a `ForkId` does not select that state for subsequent Solidity calls.

## Adaptation requirements

A complete adapter must read the oracle actually used by the covered operation, at the relevant call snapshot. Use `ph.staticcallAt` or `_readUintAt` with that fork, bind the expected oracle, and reject future timestamps explicitly. Set maximum age from the feed's update policy. A 600-second limit is an example, not a universal feed requirement.

## Scenarios

These outcomes describe the timestamp comparison once the read is bound to the correct snapshot. Direct getter calls in the isolated assertion runtime can revert before the comparison.

| Scenario | Meaning |
| --- | --- |
| Reported age is exactly 600 seconds | Within the age bound |
| Reported age is 601 seconds | Outside the age bound |
| Timestamp is in the future | Unsigned subtraction reverts |
| Fresh timestamp accompanies a manipulated price | Freshness alone does not reject it |

Use [oracle checks on risk-increasing calls](./reusable-patterns#oracle-reduce-only-gate) for an independent reference comparison. Protocols with in-transaction price updates need a check on the consumed price, as in the [Aave oracle examples](https://github.com/phylaxsystems/credible-std/blob/fe49de6dcddb8ea1f77ea2828a0c9d7d5f923db0/examples/aave/README.md).
