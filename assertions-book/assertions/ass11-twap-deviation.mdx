A price-sensitive operation should reject a spot price far from an independent time-weighted reference. This legacy template illustrates that goal but needs correction before use.

<Warning>
The reviewed upstream example needs correction before production use. The limitation below is present in the linked source; the imported code is preserved for comparison.
</Warning>

## Source limitation

The template creates pre- and post-transaction fork identifiers, then calls `twap()` and `price()` directly. The identifiers are not passed into those reads. Its deviation calculation also divides to a whole percentage before comparison: a 5.9% deviation rounds down to 5% and passes the nominal 5% limit.

## Adaptation requirements

Bind the spot and reference reads to explicit snapshots. Compare scaled products before division, with overflow-safe arithmetic, and define how a zero reference is handled. Validate the reference window, decimals, and independence from the operation being protected.

## Scenarios

| Scenario | Meaning |
| --- | --- |
| Spot 105; reference 100 | At the intended 5% boundary |
| Spot 105.9; reference 100 | The arithmetic truncates to 5%; a correct 5% comparison must reject it |
| Reference is zero | The template divides by zero |
| Price spikes and is restored before transaction end | Requires observation at the consumed-price boundary |

Use the [oracle reduce-only pattern](./reusable-patterns#oracle-reduce-only-gate) for a simpler pre-call comparison. That pattern uses the smaller price as its percentage denominator; it is not the same formula as deviation from a fixed TWAP.
