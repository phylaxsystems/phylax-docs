A simple receipt token issues one share per asset unit. This template requires recorded assets to cover the raw share count.

## Behavior

`ERC4626AssetsSharesAssertion` reads total assets from slot `0` and total shares from slot `1` at transaction end. Its entire inequality is `assets >= shares`.

## Configuration

Use this inequality only for an explicitly defined one-to-one accounting model with the same numeric scale. General ERC-4626 vaults can have different decimals, virtual offsets, and exchange rates. For those vaults, use the [share-price and asset-flow components](./vault-policies).

## Scenarios

| Transaction | Result |
| --- | --- |
| 1,000 asset units back 900 same-scale receipt units | Accepted |
| 900 asset units back 1,000 same-scale receipt units | Rejected |
| A valid vault uses 6 asset decimals and 18 share decimals | Raw comparison can reject healthy deposits |

## Coverage limits

This is not a general ERC-4626 compliance or solvency invariant. A share price below one can be valid. The example also trusts recorded total assets; it does not independently value strategies or verify token custody.
