A token issuer requires approved callers for its mint and transfer entry points. This template checks those callers against a configured registry.

## Behavior

`OnlyAccreditedCanMintAssertion` registers the example's mint and transfer selectors. It scans successful `CALL` frames to the adopter, up to 32 matches per selector, and checks each immediate caller's accreditation.

## Configuration

Pass the registry address to the constructor. Replace the example interface with the token's exact selectors and confirm that the registry implements the expected lookup. Decide whether accreditation applies to the operator, recipient, sender, or all three before adapting the policy.

<Warning>
The source calls the registry directly. Adapt that lookup to an explicit snapshot read with `ph.staticcallAt` before using it in the isolated assertion runtime. The table describes the intended caller policy once that lookup is available.
</Warning>

## Scenarios

| Transaction | Result |
| --- | --- |
| Accredited caller invokes a covered function | Accepted |
| Unaccredited immediate caller invokes it | Rejected |
| Accredited router sends tokens to an unaccredited recipient | Recipient is not checked by this template |

## Coverage limits

The template does not check recipients or the original transaction sender. Its `CALL` filter and bounded scan are not complete coverage of arbitrary proxy or batch traces. Test the deployed call structure, including batches above the scan bound. For address-argument screening, see the [Cap example](https://github.com/phylaxsystems/credible-std/blob/fe49de6dcddb8ea1f77ea2828a0c9d7d5f923db0/examples/cap/src/CapOfacComplianceAssertion.sol).
