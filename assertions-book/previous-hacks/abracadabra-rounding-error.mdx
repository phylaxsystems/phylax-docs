## What Happened

The pinned CauldronV4 source tracks debt using `elastic` amounts and `base` shares. `repayForAll` and the conversion paths must preserve a meaningful relationship between the two. Reducing the debt amount while leaving shares outstanding creates a precision-sensitive state; a ratio computed from that state is not an independent solvency check. [Pinned CauldronV4 source](https://github.com/Abracadabra-money/abracadabra-money-contracts/blob/cb97c71c8fbfecbd0080e0cfa877f2dc37f56950/src/cauldrons/CauldronV4.sol).

## Attack Mechanism

Cauldron debt uses a rebase: `elastic` is the debt amount and `base` is the total number of debt shares. A user's debt is derived from their share of `base`, scaled by `elastic`.

`repayForAll` reduces the amount owed without necessarily reducing every borrower's shares. When the amount becomes very small relative to the share count, integer rounding becomes significant. Reaching `elastic = 0` with `base > 0` is particularly dangerous: conversion code may take its zero-value initialization branch while old shares still exist.

Consider a state with no debt amount but a large outstanding share count. If the next borrow creates new shares at a 1:1 ratio, those shares represent only a tiny fraction of the old total. A subsequent debt calculation can understate the new borrower's obligation. A solvency check based on that same damaged ratio is not an independent safeguard.

The narrow assertion below rejects the zero-amount/nonzero-shares state. It uses `staticcallAt` to read `totalBorrow()` at transaction end.

## Assertion Example

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.29;

import {Assertion} from "credible-std/Assertion.sol";
import {AssertionSpec} from "credible-std/SpecRecorder.sol";
import {PhEvm} from "credible-std/PhEvm.sol";

/// @notice Reject a zero debt amount with outstanding debt shares at transaction end.
contract DebtShareConsistency is Assertion {
    constructor() { registerAssertionSpec(AssertionSpec.Reshiram); }
    function triggers() external view override { registerTxEndTrigger(this.check.selector); }
    function check() external view {
        (uint128 elastic, uint128 base) = abi.decode(read(ph.getAssertionAdopter(),
            abi.encodeWithSignature("totalBorrow()"), _postTx()), (uint128, uint128));
        require(elastic != 0 || base == 0, "Debt shares without debt");
    }

    function read(address target, bytes memory data, PhEvm.ForkId memory fork)
        internal view returns (bytes memory)
    {
        PhEvm.StaticCallResult memory result = ph.staticcallAt(target, data, 500_000, fork);
        require(result.ok, "Snapshot read failed");
        return result.data;
    }
}
```

## What This Check Covers

This check only covers the stated zero state at transaction end. It can miss a temporary inconsistent state or harmful rounding while `elastic` remains positive. Debt forgiveness, repayment, borrow conversions, and each operation's solvency need separate tests; do not treat this one condition as a complete replay of the exploit.
