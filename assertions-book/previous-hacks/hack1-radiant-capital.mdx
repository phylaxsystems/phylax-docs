## What Happened

Radiant’s reimbursement proposal identifies the October 16, 2024 multisig exploit as causing over $50 million in losses. The case concerns compromised authorization and subsequent control of protocol assets, rather than a mathematical error in lending accounting. [Radiant reimbursement proposal](https://community.radiant.capital/t/feedback-101-deploying-merged-claim-contracts-for-radiant-depositor-reimbursement/1936).

## Attack Mechanism

The attacker obtained enough signing authority to approve changes to Radiant's lending-pool administration. Once control moved, the attacker could redirect protocol behavior and move assets. The lending arithmetic did not have to fail: the transaction was dangerous because it changed who controlled the contracts.

The relevant authority has several parts. The addresses provider has an owner, a pool admin, and an emergency admin. Protecting only `owner()` leaves the other roles outside the rule. The assertion below compares all three roles before and after the transaction, using explicit Reshiram snapshot calls.

A legitimate administration transfer also changes these values. A freeze policy therefore requires a planned policy update before a legitimate transfer; an allowlist policy is an alternative when transfers to known successors should remain possible.

## Assertion Example

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.29;

import {Assertion} from "credible-std/Assertion.sol";
import {AssertionSpec} from "credible-std/SpecRecorder.sol";
import {PhEvm} from "credible-std/PhEvm.sol";

/// @notice Freeze the provider's owner, pool admin, and emergency admin at transaction boundaries.
contract RadiantAuthority is Assertion {
    constructor() { registerAssertionSpec(AssertionSpec.Reshiram); }
    function triggers() external view override { registerTxEndTrigger(this.check.selector); }
    function check() external view {
        address provider = ph.getAssertionAdopter();
        bytes[3] memory getters = [abi.encodeWithSignature("owner()"),
            abi.encodeWithSignature("getPoolAdmin()"), abi.encodeWithSignature("getEmergencyAdmin()")];
        for (uint256 i; i < getters.length; ++i) {
            address beforeRole = abi.decode(read(provider, getters[i], _preTx()), (address));
            address afterRole = abi.decode(read(provider, getters[i], _postTx()), (address));
            require(beforeRole == afterRole, "Authority changed");
        }
    }

    function read(address target, bytes memory data, PhEvm.ForkId memory fork)
        internal view returns (bytes memory)
    {
        PhEvm.StaticCallResult memory result = ph.staticcallAt(target, data, 500_000, fork);
        require(result.ok, "Snapshot read failed");
        return result.data;
    }
}
```

## What This Check Covers

Attach this check to the addresses provider that owns these getters. It rejects a lasting role change; it does not detect a role changed and restored within one transaction, implementation upgrades that preserve the roles, or transfers already available to an unchanged authorized signer.
